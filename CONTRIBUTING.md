# Contributing to Awesome Obsidian

Thank you for your interest in contributing to **Awesome Obsidian**! Please follow these guidelines to keep the list clean, high-quality, and compliant with the [Awesome list standards](https://github.com/sindresorhus/awesome/blob/main/pull_request_template.md).

## Guidelines

1. **Search first:** Check the existing list and open pull requests to ensure your suggestion is not a duplicate.
2. **Quality over quantity:** Only submit tools, plugins, themes, or resources that are genuinely useful, well-maintained, and add real value to the Obsidian ecosystem.
3. **One item per pull request:** Please open a separate pull request for each individual addition so each item can be reviewed cleanly.
4. **Alphabetical order:** Place new entries in alphabetical order within their appropriate category.
5. **Formatting:** Follow the exact entry format used throughout `README.md`:
   ```markdown
   * [**Project Name**](https://link-to-repo-or-site) — Concise, objective description starting with a capital letter and ending with a period.
   ```
   * Keep descriptions brief, factual, and free of promotional hype (avoid words like "best," "revolutionary," or "must-have").
   * Add applicable legend badges (`⭐` Essential, `🖥️` Desktop Only, `🌐` Official Tool) only when accurate.
6. **Direct links:** Link directly to the project's primary GitHub repository or official homepage—never use URL shorteners, affiliate links, or paywalled blog posts.
7. **Core redundancy:** Do not submit plugins whose core functionality has been completely superseded by native Obsidian features unless the plugin still offers substantial unique capabilities.
8. **New categories:** Create a new category only when at least 3–5 distinct, high-quality items belong in it.

## Updating or Removing Entries

* **Dead or archived projects:** If a plugin, theme, or tool has been archived, abandoned for years, or broken by recent Obsidian releases, feel free to open a PR to remove it or flag it with a clear explanation.
* **Improved descriptions:** PRs that clarify descriptions, fix broken URLs, or update renamed plugins are always welcome.

## Pull Request Checklist

Before submitting your PR, please verify:

* [ ] The item is not already in the list.
* [ ] The entry is placed in the most relevant category in alphabetical order.
* [ ] The link works and points directly to the official source.
* [ ] The description starts with a capital letter, ends with a period, and is concise.
* [ ] There are no trailing whitespaces or broken Markdown formatting.
